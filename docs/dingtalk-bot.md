# 钉钉机器人手机交互

入口：设置 → 手机交互。电脑需开机、联网并运行岛仔；休眠和关机期间不处理消息。

## 安装与登录

未安装官方 DWS 组件时，点击「一键安装组件」。安装在后台完成，支持取消、失败重试和重新检测，不安装 AI 技能包；官方安装器可能将组件目录加入当前用户 PATH。已有组件不重复安装。首次需个人登录授权，步骤见 [个人授权说明](dingtalk-login.md)。

## 任务通知

刷新机器人列表，选择专供岛仔使用的应用机器人，开启「通过机器人通知我本人」。应用须有发消息权限，本人须在应用可见范围内。

通知仅显示 AI 回复正文，不显示来源、状态、任务名或关联码。回复内容最多 1500 字；无法读取时明确提示，不使用其他任务的结果。目前内容读取支持 Codex 完成任务，可在设置中关闭回复内容显示。

可选择仅锁屏时通知。后台约每 15 秒检查一次，仅发送启用后新观察到的完成、失败和待确认事件，不补发历史状态或未锁屏期间跳过的事件。一次最多发送两条，其余保留到后续检查；过时的待发状态会丢弃。

发送前保存去重记录。平台返回有效凭据且无无效或限流收件人才显示「钉钉已接收」，不表示消息已读。失败或结果不明时不自动重发，请先核对机器人单聊。

## 回复继续任务

通知推送与回复接收分别由各自的开关控制。单条通知失败不再退出整个发送监听或自动关闭通知开关，后续新通知继续发送；失败或结果不明的旧通知不自动重放。发送线程本身异常退出或无法启动时保留开关并明确提示暂停，可关闭后重新开启恢复。关闭「通过机器人通知我本人」或通知发送失败暂停推送时，只要回复开关保持开启、账号与机器人有效，仍然接收手机消息。关闭回复开关、退出登录或更换机器人时才停止对应的接收连接。普通文字仍需有有效的任务通知关联；没有关联时返回提示，不猜测其他任务。

开启「允许我回复机器人，继续 Codex 原任务」。官方组件检查应用与凭证，并启动 Stream 接收，不需要公网入站端口。机器人须已发布 Stream 模式，当前用户须有相应应用管理权限。启动进程不代表已成功连通，可以从手机发送「/tasks」验证。

- 未引用的普通文字默认回复本会话上一条任务通知；上一条已处理、过期或任务已更新时提示重新选择，不改投更早的任务。
- 引用具体通知时，按其消息 ID 回复指定任务，优先于默认上一条。
- 以 `/` 开头的消息仅作为命令，不作为普通回复转发模型；`/help` 查看帮助，未知命令返回提示。
- 没有有效通知时，不发送任务指令。
- 明确引用了失效消息时，不改投其他任务。
- 「/tasks」按最近更新排序，每页 5 项，以 Markdown 分点显示，每项一行「任务名 · 回复标识」，页尾统一说明回复方式；发送「/tasks 2」翻页。仅列出本机当前账号与机器人下可继续的通知。

每条通知只能回复一次，24 小时后过期。原任务状态或轮次更新后，旧通知不能继续使用。回执中的「已排队」仅表示普通用户消息已送入精确的 Codex 原任务 UUID，不创建副本，不改变模型、运行权限或审批要求。原客户端未加载任务或仍需审批时，可能尚未执行。

目前只接收当前用户的单聊，不接入群消息、文件和图片指令，也不支持继续 Claude Code 原任务。机器人名称为 claude 不代表执行模型切换为 Claude。

请使用专用机器人；多个设备同时接同一机器人可能分流消息。连接失败不会反复自动重启，处理网络、权限或连接冲突后可关闭再开启回复。岛仔退出时会结束自己托管的接收进程。新收发组件使用结构化参数，不要求程序路径没有空格。

## 引用定位与本机记录

收发组件适配自 [soimy/openclaw-channel-dingtalk](https://github.com/soimy/openclaw-channel-dingtalk)，使用相同的 dingtalk-stream SDK，不安装或启动 OpenClaw。应用凭证通过现有官方 DWS 个人授权获取，仅经匿名管道传入子进程内存，不写入配置、命令行或日志。通知与回复显式使用 Markdown，短列表不再依赖字数判断；通知 HTTP 使用与上游相同的 Axios 通道。旧 DWS Stream 自定义命令与 Markdown 补丁组件已移除。

首次发送通知后仍可确认并保存真实「会话 ID＋消息 ID」关联。收到引用时，优先读取 Stream 回调直接提供的原发送回执 originalProcessQueryKey，精确查找保存的发送回执；没有回执时按原消息 ID 定位。两种标识分别保存，不把回执当作消息 ID。无需从 DWS 接收日志猜当前消息，也不按引用正文匹配；明确引用却没有可用标识时不改投上一条任务。

新通知未确认消息 ID 时，如果回调提供原发送回执，仍可引用定位；两种标识都不可用时使用 `/tasks` 备用指令。旧记录里已保存的发送回执可继续使用，没有任何精确关联的历史通知不按正文或时间猜测。首次发送绑定的正文确认保留。

组件仅接受当前授权用户的私聊文本，忽略群聊、其他用户和附件；按会话串行处理，限制积压与重复回调。岛仔在实际转发前持久化接收消息摘要标识，并再次校验账号、机器人、原任务轮次、过期和已消费状态。发送结果不明不自动重放任务。连接断开后不反复抢占，处理网络或冲突后关闭再开启回复。

Stream 只有在 SDK connected 为真且实际 WebSocket 为 OPEN 后才显示已连接；SDK 的 connect() 提前返回不视为握手成功。服务端可能直接投递消息而不发送独立 REGISTERED 事件，因此不强制要求 SDK registered 标记。握手最多等待约 40 秒，整体组件启动仍受超时保护。断开或失败后可在手机交互页点击「重新连接」，无需先关再开回复开关。诊断日志额外记录 WebSocket 关闭码、握手超时以及可获取的升级请求 HTTP 状态；不会仅凭断开就断言是其他设备抢占。

本机记录包括 dingtalk-bot-settings.json、dingtalk-bot-ledger.json、dingtalk-reply-routes.json 和 dingtalk-inbound-journal.json；接收去重日志仅存摘要键和时间，不存聊天正文。它们不参与云同步。旧 dingtalk-reply-events.json 与 dingtalk-reply-diagnostics.json 不再读取或更新，不自动删除历史文件。

旧待办传输、轮询和界面已移除，历史测试待办及本机旧文件不自动删除。没有跨设备统一转发或去重。

## 构建与交付

运行 `scripts/build-dingtalk-bridge.ps1`（构建环境需要 Node.js 24+ 和 npm）。脚本使用 package-lock.json 安装固定依赖，执行合成测试，打包桥接代码与 Node 运行时，并保存来源、许可证和 SHA-256。输出在 prebuilt/dingtalk/；交付放入主程序旁的 components/dingtalk/，用户无需额外安装 Node 或 OpenClaw。官方 DWS 仍用于个人登录、查询与机器人应用授权。安装包和免安装包会包含该目录；发布及 CI 打包步骤已加入组件构建。

请保留 components 文件夹。只有主程序而缺少收发组件时会明确提示，不悄悄退回旧连接器。

## 诊断日志

新版从启动后开始记录本机 `dingtalk-diagnostics.json`（默认 `%APPDATA%\Daozai\dingtalk-diagnostics.json`），不参与云同步。最多保留最近 7 天、400 条，自动淘汰旧记录；日志写入失败不改变任务处理结果。

收发组件校验失败时，设置页会显示出问题的文件名，日志会记录 `NODE_EXE_*` 或 `BRIDGE_CJS_*`，区分文件缺失、类型错误、访问被拒绝和其他读取错误。安装包构建会核对这两个文件的 SHA-256，校验失败时报告具体文件。

每条包含 UTC 时间戳 `at`、操作 `operation`、阶段 `stage`、结果 `outcome`、错误码 `code`、可获得的 HTTP 状态 `http_status`、耗时 `elapsed_ms`、尝试次数 `attempt`、重试次数 `retry_count` 和关联摘要 `correlation`。应用、机器人和凭证的只读查询失败时最多尝试 3 次，退避间隔 1、2 秒，日志如实记录 attempt 与 retry_count；真正的消息投递结果不明时不盲目重发。HTTP/API 错误通过结构化结果传回，不再因子进程失败丢失；DWS 授权命令未提供具体平台状态时记为 `DWS_COMMAND_FAILED` 并标明阶段，不编造错误详情。

覆盖授权查询、获取令牌、投递通知、绑定消息 ID、Stream 建连/断开、回调筛选与去重、任务路由和回复投递。通知开关关闭时记录 `USER_DISABLED_NOTIFICATIONS` 或 `ROBOT_CHANGED`；发送监听异常暂停记录 `NOTIFICATION_WORKER_PAUSED`，保留开关，便于区分手动操作和程序异常。

日志不记录密钥、令牌、Webhook URL、消息正文、任务名称、原始会话/消息 ID、完整服务端响应或自由文本异常堆栈。仅保留错误码等固定字段，关联值使用摘要。旧版没有保存的错误详情无法补回。

## 验证范围

自动检查覆盖任务定位、上一条默认回复、指定引用定位、斜杠命令拦截、旧消息拒绝、账号隔离、逐条去重、发送不确定结果不重放及进程退出保护。真实手机收发、原客户端实际执行，以及全新设备安装仍需用户验证。
